# Security and limitations

A candidate must be within the sealed catalogue; observations must be truthful and properties stable. The contract cannot establish physical identity or fetch device telemetry. Unknown values are adversarial possibilities, not probabilities. The finite guarantee applies to the accepted matrix, not to objective truth. A non-reducing question cannot help against worst-case unknown observations. No expected-cost optimization is claimed.

Input text is public and untrusted. Prompts explicitly prohibit following embedded instructions, but prompt injection resistance is not guaranteed. Consensus reduces reliance on one answer; validators may share model biases or disagree. No oracle accuracy, censorship resistance, production readiness or Sybil resistance is claimed.

Immutable owner namespaces and expected revisions prevent other senders overwriting an assessment. Certification is terminal and state is written only after semantic consensus and deterministic derivation. This owner controls when assessment occurs, but cannot submit or override the accepted semantic table. Bounds cap deterministic work and per-owner storage; they do not prevent arbitrary new owners.

Semantic errors, provider failure and malformed output fail closed. U is reserved for ambiguity in the declarations, never infrastructure failure. The contract has no funds, payable operations, token approvals, network switching, appeals or administrative rewrite path.

Real negative semantic controls are not claimed unless explicitly indexed in EVIDENCE.md. Exhaustive algorithm checks and scripted validator rejection tests remain local evidence. The disposable test signer is excluded from source and downloadable artifacts; deploy a new record from your own wallet when ownership is needed. Existing examples remain publicly readable.
